    27→    27→## 1. Présentation générale
    28→    28→
    29→    29→### Objet
    30→    30→
    31→    31→Application web pour la gestion de trois registres de santé et sécurité au travail au sein de la DREETS Bourgogne-Franche-Comté (direction régionale de l'économie, de l'emploi, du travail et des solidarités).
    32→    32→
    33→    33→### Trois registres
    34→    34→
    35→    35→| Code | Nom complet | Couleur | Description |
    36→    36→|------|-------------|---------|-------------|
    37→    37→| RSST | Registre de Santé et de Sécurité au Travail | Bleu (`var(--rsst-color)`) | Signalements généraux de santé et sécurité |
    38→    38→| RAMI | Registre des Actes d'Agressions, de Menaces et d'Incivilités | Gris (`var(--rami-color)`) | Signalements d'agressions, menaces ou incivilités |
    39→    39→| DGI | Registre de signalement d'un Danger Grave et Imminent | Rouge (`var(--dgi-color)`) | Signalements de dangers graves et imminents |
    40→    40→
    41→    41→### Trois rôles
    42→    42→
    43→    43→| Rôle | Code | Permissions |
    44→    44→|------|------|-------------|
    45→    45→| Agent | `agent` | Créer des signalements, consulter les signalements (selon visibilité), modifier ses propres signalements |
    46→    46→| Superviseur | `superviseur` | Permissions agent + répondre aux signalements, abandonner des signalements, synthèse, export, statistiques, gestion des utilisateurs, paramètres |
    47→    47→| Membre CHSCT | `chsct` | Consulter tous les signalements (tous sites), synthèse, export, statistiques — lecture seule, pas de réponse ni d'abandon |
    48→    48→
    49→    49→> **Note** : Il n'y a pas de rôle « Manager ». Les trois seuls rôles sont `agent`, `superviseur` et `chsct`.
    50→    50→
    51→    51→### États d'un signalement
    52→    52→
    53→    53→```
    54→    54→Nouveau → En cours → Traité
    55→    55→  └──→ Abandonné (soft delete, possible depuis n'importe quel état non traité)
    56→    56→```
    57→    57→
    58→    58→| État | Code | Badge CSS |
    59→    59→|------|------|-----------|
    60→    60→| Nouveau | `nouveau` | `badge--nouveau` |
    61→    61→| En cours | `en_cours` | `badge--en-cours` |
    62→    62→| Traité | `traite` | `badge--traite` |
    63→    63→| Abandonné | `abandonne` | `badge--abandonne` |
    64→    64→
    65→    65→### Sites (Unités Régionales — UR)
    66→    66→
    67→    67→Les sites sont stockés dans la table `sites`. Par défaut, deux sites sont créés lors de l'initialisation :
    68→    68→
    69→    69→| Code | Nom | Département |
    70→    70→|------|-----|-------------|
    71→    71→| UR21 | UR Côte-d'Or | Côte-d'Or |
    72→    72→| UR25 | UR Doubs | Doubs |
    73→    73→
    74→    74→D'autres sites peuvent être ajoutés via l'interface de paramétrage (onglet « Gestion des sites »). Le libellé des unités (« UR », « UD », etc.) est configurable via `app_label_unite`.

   193→   193→## 3. Schéma de la base de données
   194→   194→
   195→   195→### Relations entre entités
   196→   196→
   197→   197→```
   198→   198→sites ──1:N── users
   199→   199→sites ──1:N── reports
   200→   200→users ──1:N── reports (declarant)
   201→   201→users ──1:N── reports (repondant)
   202→   202→users ──1:N── reports (pour_compte_de)
   203→   203→reports ──1:N── report_responses
   204→   204→sites ──1:N── notification_settings
   205→   205→```
   206→   206→
   207→   207→### Table `sites`
   208→   208→
   209→   209→Stocke les Unités Régionales (UR). Deux sites par défaut, extensibles via l'UI.
   210→   210→
   211→   211→```sql
   212→   212→CREATE TABLE IF NOT EXISTS sites (
   213→   213→    id              INTEGER PRIMARY KEY AUTOINCREMENT,
   214→   214→    code            TEXT NOT NULL UNIQUE,           -- ex: "UR21", "UR25"
   215→   215→    nom             TEXT NOT NULL,                   -- ex: "UR Côte-d'Or"
   216→   216→    departement     TEXT,                            -- ex: "Côte-d'Or"
   217→   217→    is_active       INTEGER NOT NULL DEFAULT 1,      -- 0 = désactivé, n'apparaît plus dans les listes
   218→   218→    created_at      TEXT NOT NULL DEFAULT (datetime('now'))
   219→   219→);
   220→   220→```
   221→   221→
   222→   222→### Table `users`
   223→   223→
   224→   224→Utilisateurs de l'application. Créés automatiquement à partir du login Windows (IIS) ou via le formulaire mock en dev.
   225→   225→
   226→   226→```sql
   227→   227→CREATE TABLE IF NOT EXISTS users (
   228→   228→    id              INTEGER PRIMARY KEY AUTOINCREMENT,
   229→   229→    username        TEXT NOT NULL UNIQUE,            -- Login Windows (ex: "jean.martin")
   230→   230→    nom             TEXT NOT NULL,                   -- Nom de famille
   231→   231→    prenom          TEXT NOT NULL,                   -- Prénom
   232→   232→    email           TEXT,                            -- Adresse e-mail
   233→   233→    role            TEXT NOT NULL DEFAULT 'agent',   -- 'agent' | 'superviseur' | 'chsct'
   234→   234→    site_id         INTEGER,                         -- FK vers sites (NULL jusqu'au choix du site)
   235→   235→    is_active       INTEGER NOT NULL DEFAULT 1,      -- Soft delete : 0 = désactivé
   236→   236→    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
   237→   237→    updated_at      TEXT NOT NULL DEFAULT (datetime('now')),
   238→   238→    FOREIGN KEY (site_id) REFERENCES sites(id)
   239→   239→);
   240→   240→```
   241→   241→
   242→   242→> **Note** : `site_id` est nullable. Un nouvel utilisateur auto-provisionné n'a pas de site tant qu'il n'a pas choisi le sien sur la page `choose_site`.
   243→   243→
   244→   244→### Table `reports`
   245→   245→
   246→   246→Table principale pour les trois registres.
   247→   247→
   248→   248→```sql
   249→   249→CREATE TABLE IF NOT EXISTS reports (
   250→   250→    uuid            TEXT PRIMARY KEY,                -- UUID v4 (ex: "a1b2c3d4-e5f6-7890-abcd-ef1234567890")
   251→   251→    reference       TEXT NOT NULL UNIQUE,            -- ex: "rsst-25-001"
   252→   252→    type            TEXT NOT NULL,                   -- 'rsst' | 'rami' | 'dgi'
   253→   253→    objet           TEXT NOT NULL,                   -- Objet du signalement, max 100 caractères
   254→   254→    description     TEXT NOT NULL,                   -- Description complète, max 20 000 caractères
   255→   255→    date_evenement  TEXT NOT NULL,                   -- Date de l'événement (ISO 8601)
   256→   256→    heure_evenement TEXT,                            -- Heure de l'événement (HH:MM)
   257→   257→    lieu            TEXT,                            -- Lieu de l'événement
   258→   258→    -- Déclarant (personne qui dépose le signalement)
   259→   259→    declarant_id    INTEGER NOT NULL,                -- FK vers users
   260→   260→    declarant_nom   TEXT NOT NULL,                   -- Nom dénormalisé pour performance
   261→   261→    declarant_prenom TEXT NOT NULL,                  -- Prénom dénormalisé
   262→   262→    -- « Pour le compte de » (RAMI uniquement)
   263→   263→    pour_compte_de  INTEGER,                         -- FK vers users (nullable, RAMI uniquement)
   264→   264→    pour_compte_nom TEXT,                            -- Nom de l'agent concerné
   265→   265→    pour_compte_prenom TEXT,                         -- Prénom de l'agent concerné
   266→   266→    -- Rattachement
   267→   267→    site_id         INTEGER NOT NULL,                -- FK vers sites (UR où l'événement s'est produit)
   268→   268→    -- Gestion d'état
   269→   269→    etat            TEXT NOT NULL DEFAULT 'nouveau', -- 'nouveau' | 'en_cours' | 'traite' | 'abandonne'
   270→   270→    is_confidential INTEGER NOT NULL DEFAULT 1,      -- 1 = confidentiel, 0 = public (mode confidential)
   271→   271→    -- Répondant (superviseur qui a traité le signalement)
   272→   272→    repondant_id    INTEGER,                         -- FK vers users (nullable)
   273→   273→    date_reponse    TEXT,                            -- Date de la réponse
   274→   274→    reponse         TEXT,                            -- Texte de la réponse
   275→   275→    -- Pièce jointe (mono-fichier, stockée en BLOB dans la base)
   276→   276→    attachment_blob BLOB,                            -- Contenu du fichier (max ~10 Mo)
   277→   277→    attachment_name TEXT,                            -- Nom du fichier original (ex: "photo_danger.jpg")
   278→   278→    attachment_mime TEXT,                            -- Type MIME (ex: "image/jpeg", "application/pdf")
   279→   279→    -- Horodatage
   280→   280→    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
   281→   281→    updated_at      TEXT NOT NULL DEFAULT (datetime('now')),
   282→   282→    FOREIGN KEY (declarant_id) REFERENCES users(id),
   283→   283→    FOREIGN KEY (pour_compte_de) REFERENCES users(id),
   284→   284→    FOREIGN KEY (repondant_id) REFERENCES users(id),
   285→   285→    FOREIGN KEY (site_id) REFERENCES sites(id)
   286→   286→);
   287→   287→```
   288→   288→
   289→   289→### Table `report_responses`
   290→   290→
   291→   291→Historique des réponses à un signalement (audit trail). Chaque réponse du superviseur est enregistrée ici.
   292→   292→
   293→   293→```sql
   294→   294→CREATE TABLE IF NOT EXISTS report_responses (
   295→   295→    id              INTEGER PRIMARY KEY AUTOINCREMENT,
   296→   296→    report_uuid     TEXT NOT NULL,                    -- FK vers reports(uuid)
   297→   297→    user_id         INTEGER NOT NULL,                -- FK vers users (le superviseur)
   298→   298→    reponse         TEXT NOT NULL,                   -- Texte de la réponse
   299→   299→    nouvel_etat     TEXT,                            -- Changement d'état : 'en_cours' | 'traite'
   300→   300→    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
   301→   301→    FOREIGN KEY (report_uuid) REFERENCES reports(uuid) ON DELETE CASCADE,
   302→   302→    FOREIGN KEY (user_id) REFERENCES users(id)
   303→   303→);
   304→   304→```
   305→   305→
   306→   306→### Table `notification_settings`
   307→   307→
   308→   308→Adresses e-mail de notification par site et globales.
   309→   309→
   310→   310→```sql
   311→   311→CREATE TABLE IF NOT EXISTS notification_settings (
   312→   312→    id              INTEGER PRIMARY KEY AUTOINCREMENT,
   313→   313→    site_id         INTEGER,                         -- FK vers sites. NULL = global
   314→   314→    type            TEXT NOT NULL,                   -- 'site' | 'global'
   315→   315→    registry        TEXT NOT NULL,                   -- 'rsst' | 'rami' | 'dgi' | 'all'
   316→   316→    email           TEXT NOT NULL,                   -- Adresse e-mail
   317→   317→    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
   318→   318→    FOREIGN KEY (site_id) REFERENCES sites(id)
   319→   319→);
   320→   320→```
   321→   321→
   322→   322→### Table `report_sequence`
   323→   323→
   324→   324→Séquence auto-incrémentée par registre et par année pour la génération des références.
   325→   325→
   326→   326→```sql
   327→   327→CREATE TABLE IF NOT EXISTS report_sequence (
   328→   328→    id              INTEGER PRIMARY KEY AUTOINCREMENT,
   329→   329→    type            TEXT NOT NULL,                   -- 'rsst' | 'rami' | 'dgi'
   330→   330→    year            INTEGER NOT NULL,                -- ex: 2025
   331→   331→    last_sequence   INTEGER NOT NULL DEFAULT 0,      -- Dernier numéro de séquence utilisé
   332→   332→    UNIQUE(type, year)
   333→   333→);
   334→   334→```
   335→   335→
   336→   336→### Table `config_app`
   337→   337→
   338→   338→Configuration applicative (magasin clé-valeur, éditable via l'UI).
   339→   339→
   340→   340→```sql
   341→   341→CREATE TABLE IF NOT EXISTS config_app (
   342→   342→    cle             TEXT PRIMARY KEY,                -- Clé de configuration
   343→   343→    valeur          TEXT,                            -- Valeur
   344→   344→    type            TEXT DEFAULT 'text',             -- 'text' | 'number' | 'password' | 'email'
   345→   345→    categorie       TEXT DEFAULT 'app',              -- 'app' | 'smtp'
   346→   346→    libelle         TEXT,                            -- Libellé affiché dans l'UI
   347→   347→    modifiable      INTEGER DEFAULT 1,               -- 1 = modifiable via l'UI
   348→   348→    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
   349→   349→    updated_at      TEXT NOT NULL DEFAULT (datetime('now'))
   350→   350→);
   351→   351→```
   352→   352→
   353→   353→### Index
   354→   354→

   480→   480→
   481→   481→**URL** : `index.php?page=login`
   482→   482→**Accès** : Public (uniquement en mode DEV)
   483→   483→**Méthode** : GET (affichage), POST (traitement)
   484→   484→
   485→   485→En production, IIS gère l'authentification Windows avant que PHP ne s'exécute — cette page est donc inaccessible. En dev, un formulaire mock permet de simuler une connexion.
   486→   486→
   487→   487→#### Affichage
   488→   488→- Carte centrée sur fond gris

   492→   492→- Champ : **Mot de passe** — `<input type="password" name="password">` (cosmétique, non vérifié)
   493→   493→- Bouton : « Se connecter »
   494→   494→
   495→   495→#### Traitement POST (`handlers/login_handler.php`)
   496→   496→- Appelle `mockLogin($username)` qui appelle `findOrCreateUser($username)`
   497→   497→- Si l'utilisateur existe en base : connexion réussie
   498→   498→- Si l'utilisateur n'existe pas : création automatique avec rôle `agent` et `site_id = NULL`

   576→   576→### 5.5 Création de signalement (`pages/report_create.php`)
   577→   577→
   578→   578→**URL** : `index.php?page=report_create&type={rsst|rami|dgi}`
   579→   579→**Accès** : Tous les utilisateurs authentifiés
   580→   580→**Méthode** : GET (affichage), POST (traitement via handler)
   581→   581→
   582→   582→#### Affichage
   583→   583→- Titre adapté au type : « Inscrire un signalement — RSST/RAMI/DGI »
   584→   584→- Bande de couleur en haut du formulaire correspondant au registre
   585→   585→- Champs du formulaire :
   586→   586→
   587→   587→| Champ | Type | Requis | Max | Défaut | Notes |
   588→   588→|-------|------|--------|-----|--------|-------|
   589→   589→| `date_evenement` | `<input type="date">` | Oui | — | Date du jour | Date de l'événement |
   590→   590→| `heure_evenement` | `<input type="time">` | Non | — | Heure actuelle | Heure de l'événement |
   591→   591→| `lieu` | `<input type="text">` | Non | 200 | — | Lieu de l'événement |
   592→   592→| `objet` | `<input type="text">` | Oui | 100 | — | Objet du signalement |
   593→   593→| `description` | `<textarea rows="8">` | Oui | 20000 | — | Description complète |
   594→   594→| `attachment` | `<input type="file">` | Non | 10 Mo | — | Image (JPG, PNG, GIF) ou PDF |
   595→   595→| `site_id` | `<select>` | Oui | — | Site de l'utilisateur | L'agent voit son site seul, le superviseur voit tous les sites |
   596→   596→
   597→   597→**Champs spécifiques RAMI** (affichés uniquement si `type=rami`) :
   598→   598→
   599→   599→| Champ | Type | Requis | Notes |
   600→   600→|-------|------|--------|-------|
   601→   601→| `pour_compte` | `<input type="checkbox">` | Non | « Signaler pour le compte d'un autre agent » |
   602→   602→| `pour_compte_nom` | `<input type="text">` | Conditionnel | Affiché si `pour_compte` coché |
   603→   603→| `pour_compte_prenom` | `<input type="text">` | Conditionnel | Affiché si `pour_compte` coché |
   604→   604→
   605→   605→**Informations déclarant** (auto-remplies, lecture seule) :
   606→   606→- Nom : `$_SESSION['user']['nom']`
   607→   607→- Prénom : `$_SESSION['user']['prenom']`
   608→   608→
   609→   609→Champs cachés : `type`, `csrf_token`
   610→   610→
   611→   611→Boutons : « Valider » (couleur du registre), « Annuler » (retour à l'accueil)
   612→   612→
   613→   613→#### Traitement POST (`handlers/report_create_handler.php`)
   614→   614→
   615→   615→**Validation** :
   616→   616→1. Jeton CSRF valide
   617→   617→2. `type` parmi : `rsst`, `rami`, `dgi`
   618→   618→3. `date_evenement` valide, pas dans le futur
   619→   619→4. `objet` non vide, max 100 caractères
   620→   620→5. `description` non vide, max 20 000 caractères
   621→   621→6. `site_id` existe dans la table sites
   622→   622→7. Si RAMI et `pour_compte` coché : `pour_compte_nom` et `pour_compte_prenom` requis
   623→   623→
   624→   624→**Traitement** :
   625→   625→1. Générer la référence : `generateReference($type, date('y'), getNextSequence($pdo, $type, date('Y')))`
   626→   626→2. Insérer dans la table `reports`
   627→   627→3. Flash : « Signalement enregistré avec la référence {reference} »
   628→   628→4. Redirection vers `report_view&uuid={new_report_uuid}`

   667→   667→### 5.7 Consultation d'un signalement (`pages/report_view.php`)
   668→   668→
   669→   669→**URL** : `index.php?page=report_view&uuid={report_uuid}`
   670→   670→**Accès** : Déclarant, superviseur, CHSCT (via `canAccessReport()`)
   671→   671→**Méthode** : GET
   672→   672→
   673→   673→#### Contrôle d'accès
   674→   674→
   675→   675→La fonction `canAccessReport()` centralise les règles :
   676→   676→- **Déclarant** : toujours accès à son propre signalement
   677→   677→- **Superviseur** : accès à tous les signalements
   678→   678→- **CHSCT** : accès à tous les signalements
   679→   679→- **Agent** (non déclarant) : selon `getReportVisibility()` :
   680→   680→  - `'confidential'` → accès si signalement non confidentiel (`is_confidential = 0`) ET même site, ou si déclarant
   681→   681→  - `'agent_choice'` → accès si signalement non confidentiel (`is_confidential = 0`) ET même site, ou si déclarant (l'agent déclarant choisit la confidentialité au cas par cas)
   682→   682→  - `'public'` → accès si `report.site_id === user.site_id`
   683→   683→
   684→   684→Si le signalement est `abandonne` et que l'utilisateur n'est ni le déclarant ni superviseur/CHSCT, un avertissement est affiché.
   685→   685→
   686→   686→#### Affichage
   687→   687→Utilise le template `report_card.php` :
   688→   688→- Carte avec bande de couleur du registre
   689→   689→- Tableau de détail : référence, date/heure, lieu, objet, description, déclarant, site, état, date de création
   690→   690→- Section « Pour le compte de » (RAMI uniquement, si renseigné)

   991→   991→## 6. Système d'authentification
   992→   992→
   993→   993→### Architecture
   994→   994→
   995→   995→L'application utilise exclusivement l'authentification Windows intégrée d'IIS. **Il n'y a pas de LDAP, pas de formulaire de login en production.**
   996→   996→
   997→   997→### Flux en production (`DEV_MODE = false`)
   998→   998→
   999→   999→1. IIS authentifie l'utilisateur via Windows Authentication **avant** que PHP ne s'exécute
  1000→  1000→2. `$_SERVER['AUTH_USER']` est toujours défini (format : `DOMAIN\username` ou `username@domain`)
  1001→  1001→3. `getAuthenticatedUser()` lit `AUTH_USER`, extrait le nom d'utilisateur via `extractUsername()`
  1002→  1002→4. `findOrCreateUser()` cherche l'utilisateur en base ou le crée automatiquement
  1003→  1003→5. L'utilisateur est stocké dans `$_SESSION['user']`
  1004→  1004→
  1005→  1005→### Détection de l'environnement (APP_ENV)
  1006→  1006→
  1007→  1007→La constante `APP_ENV` est déterminée par un système de priorité à 3 niveaux :
  1008→  1008→
  1009→  1009→1. **`APP_ENV_FORCE`** (priorité maximale) : si cette constante est définie dans `config.php` (ex: `'dev'` ou `'prod'`), elle est utilisée sans vérification supplémentaire
  1010→  1010→2. **`getenv('APP_ENV')`** (priorité intermédiaire) : variable d'environnement du serveur, utile pour les déploiements sans modification de code
  1011→  1011→3. **Auto-détection via `$_SERVER['AUTH_USER']`** (priorité minimale, fallback) : si `AUTH_USER` est disponible → `prod`, sinon → `dev`
  1012→  1012→
  1013→  1013→```php
  1014→  1014→// Ordre de résolution :
  1015→  1015→defined('APP_ENV_FORCE') ? APP_ENV_FORCE : (getenv('APP_ENV') ?: (isset($_SERVER['AUTH_USER']) ? 'prod' : 'dev'))
  1016→  1016→```
  1017→  1017→
  1018→  1018→### Flux en développement (`DEV_MODE = true`)
  1019→  1019→
  1020→  1020→1. IIS n'est pas utilisé — `AUTH_USER` n'est pas disponible
  1021→  1021→2. Un formulaire mock de connexion est affiché (`pages/login.php`)
  1022→  1022→3. `mockLogin($username)` appelle `findOrCreateUser($username)` et stocke en session
  1023→  1023→
  1024→  1024→### Extraction du nom d'utilisateur
  1025→  1025→
  1026→  1026→`extractUsername(string $authUser): string` gère les formats IIS :
  1027→  1027→- `DREETS-BFC\jean.martin` → `jean.martin`
  1028→  1028→- `jean.martin@dreets-bfc.gouv.fr` → `jean.martin`
  1029→  1029→- `jean.martin` → `jean.martin`
  1030→  1030→- Résultat toujours en minuscules
  1031→  1031→
  1032→  1032→### Auto-provisionnement
  1033→  1033→
  1034→  1034→`findOrCreateUser(PDO $pdo, string $username): ?array`
  1035→  1035→- Si l'utilisateur existe en base : retourne ses données
  1036→  1036→- Si l'utilisateur n'existe pas : appelle `autoProvisionUser()`
  1037→  1037→
  1038→  1038→`autoProvisionUser(PDO $pdo, string $username): ?array`
  1039→  1039→- Génère le nom d'affichage à partir du username (ex: `jean.martin` → Jean Martin)
  1040→  1040→- Détermine le rôle via `determineProvisionRole()`
  1041→  1041→- Crée l'utilisateur avec `site_id = NULL` (choix du site à la première connexion)
  1042→  1042→- Email auto-généré : `{username}@dreets.gouv.fr`
  1043→  1043→
  1044→  1044→### Attribution du rôle superviseur
  1045→  1045→
  1046→  1046→Deux méthodes :
  1047→  1047→
  1048→  1048→1. **Via l'interface** : un superviseur peut modifier le rôle d'un utilisateur via la page `user_edit` → `updateUser()`
  1049→  1049→
  1050→  1050→2. **Via la liste de configuration** (`app_superviseur_usernames`) :
  1051→  1051→   - Liste séparée par virgules de logins Windows (ex: `jean.martin, sophie.dupont`)
  1052→  1052→   - `determineProvisionRole()` vérifie cette liste lors de l'auto-provisionnement
  1053→  1053→   - `checkAndPromoteUser()` vérifie la liste **à chaque requête** (pas uniquement à la connexion) et promeut automatiquement un agent existant si son username y figure
  1054→  1054→   - Utile pour la première installation : permet de désigner les premiers superviseurs sans accès à la base de données
  1055→  1055→   - **Pas de mécanisme de préfixe** (l'ancien système auto-admin par préfixe n'existe plus)

  1059→  1059→## 7. Contrôle d'accès et visibilité
  1060→  1060→
  1061→  1061→### Fonction centrale : `canAccessReport()`
  1062→  1062→
  1063→  1063→`canAccessReport(array $report, array $user): bool`
  1064→  1064→
  1065→  1065→Centralise toutes les règles d'accès à un signalement. Un utilisateur peut consulter un signalement si et seulement si :
  1066→  1066→
  1067→  1067→- Il est le **déclarant** du signalement (`report.declarant_id === user.id`), OU
  1068→  1068→- Il a le rôle **superviseur**, OU
  1069→  1069→- Il a le rôle **CHSCT**
  1070→  1070→
  1071→  1071→Pour les agents (non déclarants du signalement consulté) :
  1072→  1072→- Si `getReportVisibility() === 'confidential'` : accès si `report.is_confidential = 0` ET `report.site_id === user.site_id`
  1073→  1073→- Si `getReportVisibility() === 'agent_choice'` : accès si `report.is_confidential = 0` ET `report.site_id === user.site_id` (l'agent déclarant choisit au cas par cas)
  1074→  1074→- Si `getReportVisibility() === 'public'` : accès si `report.site_id === user.site_id`
  1075→  1075→
  1076→  1076→### Visibilité des signalements
  1077→  1077→
  1078→  1078→`getReportVisibility(): string` — retourne le mode de visibilité pour les agents :
  1079→  1079→
  1080→  1080→| Valeur | Description | Remarque |
  1081→  1081→|--------|-------------|----------|
  1082→  1082→| `confidential` | Signalements confidentiels par défaut, l'agent ne voit que les siens + les non confidentiels de son site | **Par défaut** |
  1083→  1083→| `agent_choice` | L'agent déclarant choisit la confidentialité au cas par cas (`is_confidential`), les autres agents voient les non confidentiels de leur site | Compromis flexibilité/transparence |
  1084→  1084→| `public` | Tous les signalements du site sont visibles par tous les agents | Conforme au principe de transparence |
  1085→  1085→
  1086→  1086→Configurée via `app_report_visibility` dans `config_app`. Les superviseurs et CHSCT voient toujours tous les sites (`canSeeAllSites() === true`).
  1087→  1087→
  1088→  1088→- `'confidential'` (défaut) : l'agent voit les signalements publics de son site + ses propres signalements (même confidentiels). Chaque signalement a un flag `is_confidential` (défaut : 1). L'agent peut décocher ce flag lors de la création.
  1089→  1089→- `'agent_choice'` : même comportement que `confidential` mais l'interface indique explicitement à l'agent qu'il peut choisir la visibilité de son signalement.
  1090→  1090→- `'public'` : l'agent voit tous les signalements de son site. Le flag `is_confidential` est ignoré dans ce mode.
  1091→  1091→
  1092→  1092→Fonctions :
  1093→  1093→- `getReportVisibility()` : retourne `'confidential'`, `'agent_choice'`, `'public'` ou `'all'` (superviseur/CHSCT)
  1094→  1094→- `reportVisibilityIsConfidential()` : `getReportVisibility() === 'confidential'`
  1095→  1095→- `reportVisibilityIsAgentChoice()` : `getReportVisibility() === 'agent_choice'`
  1096→  1096→- `reportVisibilityIsPublic()` : `getReportVisibility() === 'public'`
  1097→  1097→
  1098→  1098→Compatibilité ascendante :
  1099→  1099→- Ancienne valeur `'site'` → `'public'`
  1100→  1100→- Ancienne valeur `'own'` → `'confidential'`
  1101→  1101→- Ancienne valeur `'0'` → `'public'`
  1102→  1102→- Ancienne valeur `'1'` → `'confidential'`
  1103→  1103→- `app_agent_visibility` → migrée vers `app_report_visibility`
  1104→  1104→- `agentVisibilityIsConfidential()` : alias déprécié, appelle `reportVisibilityIsConfidential()`
  1105→  1105→- `agentVisibilityIsPublic()` : alias déprécié, appelle `reportVisibilityIsPublic()`
  1106→  1106→
  1107→  1107→### Matrice des permissions par rôle
  1108→  1108→
  1109→  1109→| Action | agent | superviseur | chsct |
  1110→  1110→|--------|-------|-------------|-------|

  1133→  1133→## 8. Règles métier
  1134→  1134→
  1135→  1135→### Génération de référence
  1136→  1136→
  1137→  1137→Format : `{type}-{YY}-{NNN}`
  1138→  1138→
  1139→  1139→- `type` : `rsst`, `rami` ou `dgi`
  1140→  1140→- `YY` : année sur 2 chiffres (ex: `25`)
  1141→  1141→- `NNN` : numéro séquentiel sur 3 chiffres avec zéro-padding (ex: `001`)
  1142→  1142→
  1143→  1143→Exemples : `rsst-25-001`, `rami-25-015`, `dgi-25-003`
  1144→  1144→
  1145→  1145→La séquence est gérée par la table `report_sequence` avec un UPSERT atomique :
  1146→  1146→
  1147→  1147→```sql
  1148→  1148→INSERT INTO report_sequence (type, year, last_sequence) VALUES (:type, :year, 1)
  1149→  1149→ON CONFLICT(type, year) DO UPDATE SET last_sequence = last_sequence + 1;
  1150→  1150→```
  1151→  1151→
  1152→  1152→### « Pour le compte de » (RAMI)
  1153→  1153→
  1154→  1154→Dans le registre RAMI, un signalement peut être déposé pour le compte d'un autre agent. Les champs `pour_compte_nom` et `pour_compte_prenom` sont renseignés. Si l'agent concerné est trouvé en base, une notification e-mail lui est envoyée via `notifyPourCompte()`.
  1155→  1155→
  1156→  1156→### Désactivation de compte (soft delete)
  1157→  1157→
  1158→  1158→Les utilisateurs sont désactivés (`is_active = 0`) et non supprimés physiquement. Un utilisateur désactivé :
  1159→  1159→- Ne peut plus se connecter (`findOrCreateUser` filtre `is_active = 1`)
  1160→  1160→- N'apparaît plus dans la liste des utilisateurs actifs
  1161→  1161→- Ses signalements existants sont conservés
  1162→  1162→
  1163→  1163→### Gestion des sites
  1164→  1164→
  1165→  1165→- Les sites peuvent être ajoutés via l'onglet « Gestion des sites »
  1166→  1166→- Un site désactivé n'apparaît plus dans les listes de choix (pour les nouveaux agents)
  1167→  1167→- Les signalements existants d'un site désactivé restent accessibles
  1168→  1168→- Un site ne peut être supprimé définitivement que s'il n'a ni utilisateurs ni signalements rattachés

  1418→  1418→
  1419→  1419→La table `config_app` stocke les paramètres modifiables via l'interface. L'accès se fait par `getConfig($cle, $default)` et `updateConfig($pdo, $cle, $valeur)`.

  1439→  1439→### Cache de configuration
  1440→  1440→
  1441→  1441→`getConfig()` utilise un cache statique interne. Après un `updateConfig()`, le cache est invalidé via `clearConfigCache()` (mécanisme de flag global `$_config_cache_cleared`).
  1442→  1442→
  1443→  1443→### Auto-migration des clés
  1444→  1444→
  1445→  1445→`migrateConfigKeys(PDO $pdo)` est appelée à chaque requête et ajoute automatiquement les clés manquantes dans les bases existantes. Pour `app_report_visibility`, la migration convertit les anciennes valeurs : `'site'` → `'public'`, `'own'` → `'confidential'`, `app_agent_see_only_own = '1'` → `'confidential'`. L'ancienne clé `app_agent_visibility` est migrée vers `app_report_visibility` si cette dernière n'existe pas encore. La colonne `is_confidential` est ajoutée automatiquement à la table `reports` si elle n'existe pas. La colonne `uuid` (TEXT PRIMARY KEY) remplace l'ancien `id` (INTEGER PRIMARY KEY AUTOINCREMENT) — la migration ajoute la colonne `uuid` et la peuple avec des UUID v4 si elle n'existe pas, puis la promeut en PRIMARY KEY.
